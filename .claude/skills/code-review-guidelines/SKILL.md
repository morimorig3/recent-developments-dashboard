# コードレビューガイドライン

## レビュー観点

### 1. コード品質

- 可読性（命名、構造、コメント）
- DRY 原則（重複排除）
- 単一責任の原則
- 適切な抽象化レベル

### 2. セキュリティ

- 入力検証
- 認証・認可
- SQL インジェクション/XSS 対策
- 秘密情報の取り扱い

### 3. パフォーマンス

- 不要なループ・再計算
- N+1 問題
- メモリリーク可能性
- 非同期処理の適切さ

### 4. テスタビリティ

- テストカバレッジ
- モック可能な設計
- エッジケースの考慮

### 5. エラーハンドリング

- 例外処理の適切さ
- エラーメッセージの品質
- リカバリー戦略

## チェックリスト

### 必須（ブロッカー）

- [ ] ビルドが通るか
- [ ] テストが通るか
- [ ] リンターエラーがないか
- [ ] 秘密情報のハードコードがないか

### コード品質

- [ ] 命名は適切か
- [ ] 複雑すぎる関数はないか
- [ ] 重複コードはないか
- [ ] 未使用のインポート/変数はないか

### ドキュメント

- [ ] 公開 API の変更にはドキュメント更新があるか
- [ ] 複雑なロジックにはコメントがあるか

## フィードバックの心得

- 批判ではなく建設的に
- 「なぜ」を説明する
- 良い点も指摘する
- 具体的な修正例を提示
