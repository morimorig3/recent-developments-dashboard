# コード調査スキル

## 目的

既存の実装パターンを把握し、新規実装の参考にする。

## 調査手順

### 1. 類似機能の特定

まず、実装したい機能に近い既存機能を探す。

```
例: 「ユーザー一覧画面を作りたい」
→ 既存の一覧画面（商品一覧、注文一覧など）を探す
```

### 2. 検索パターン

#### キーワードで探す

```bash
Grep('[機能に関連するキーワード]', 'プロジェクトルート')
```

#### ファイル名で探す

```bash
Glob('**/*Controller*')
Glob('**/*Service*')
Glob('**/*Repository*')
```

#### ルーティングから探す

```bash
# CLAUDE.mdの「調査のヒント」セクションを参照
```

### 3. パターン把握のチェックリスト

調査時に確認すべき点：

#### アーキテクチャ

- [ ] レイヤー構成（Controller/Service/Repository など）
- [ ] 各レイヤーの責務
- [ ] 依存関係の方向

#### 実装パターン

- [ ] バリデーションの書き方
- [ ] レスポンスの返し方
- [ ] エラーハンドリング
- [ ] トランザクションの使い方
- [ ] ログの出力方法

#### 命名規則

- [ ] クラス名
- [ ] メソッド名
- [ ] 変数名
- [ ] ファイル名

#### その他

- [ ] 共通処理の場所
- [ ] 設定値の管理方法
- [ ] 例外クラスの使い方

### 4. 調査結果の報告形式

調査完了後、以下の形式で報告：

```markdown
## 調査結果

### 参考にすべき既存実装

- [ファイルパス]: [何の参考になるか]
- [ファイルパス]: [何の参考になるか]

### 把握したパターン

- バリデーション: [方法]
- レスポンス: [方法]
- エラーハンドリング: [方法]
- その他特徴: [内容]

### 実装時の注意点

- [注意点 1]
- [注意点 2]
```
